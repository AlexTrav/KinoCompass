# KinoCompass

[![CI](https://github.com/AlexTrav/KinoCompass/actions/workflows/ci.yml/badge.svg)](https://github.com/AlexTrav/KinoCompass/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Рубежное задание РК-2 по курсу «Искусственный интеллект и машинное обучение»: рекомендательная
система фильмов на данных MovieLens 32M – подбирает фильмы под вкус по 5–10 оценкам и объясняет,
почему именно эти. Сравниваются базовые модели, коллаборативная фильтрация, матричная факторизация,
контентная модель и нейросеть Mult-VAE.

**Сайт: https://alextrav.github.io/KinoCompass/** · API: https://kinocompass-backend.onrender.com/docs

Автор: **Алексей Нерезов**. Научный руководитель: PhD Науменко Виталий Валерьевич.

Проект завершён: сайт и API работают, к защите РК-2 подготовлены научное исследование, пояснительная записка и
презентация (сданы отдельно, в репозиторий не входят).

## Что сделано

- данные: MovieLens 32M скачивается в память при каждом запуске (на диске не хранится), каталог из
  23 349 фильмов (99 % оценок) с названиями на русском, казахском и английском из Wikidata, постерами и
  описаниями сюжета TMDb, проверка данных – [data/](data/README.md);
- исследование данных: длинный хвост популярности, поведение новичков (59 % людей не возвращаются после
  первых суток – главный сценарий холодный старт), связь оценки с популярностью и годом выпуска, жанры и
  корреляции вкусов, теги, годовые окна для разбиения по времени, 15 рисунков – [research/](research/README.md);
- честная проверка рекомендаций: разбиение по времени (обучение до 14.10.2021, валидация – год, тест –
  последний год), сценарии «новичок с 5 и 10 оценками» и «постоянный», метрики точности, покрытия,
  новизны и разнообразия, тесты значимости; базовые модели – лучшая «популярные за последний год»
  (NDCG@10 = 0,345 для новичка с 5 оценками); соседи – user-kNN вровень с ней у новичков и на 13 % лучше
  у постоянных, item-kNN хуже; матричная факторизация – ALS на 10 % лучше популярности у постоянных, но
  хуже у новичков, SVD предсказывает звёзды постоянному на 7 % точнее; лучшая модель шага – EASE (Colab, GPU):
  на 22 % лучше популярности у постоянных и на 2 % у новичка с 10 оценками; контентная модель (TF-IDF и e5 по
  тегам и описаниям) в 2,7 раза слабее популярности, а на новинках уступает простому «сначала самые новые»;
  поиск словами на e5 находит по русским запросам 5 фильмов из 5, по казахским – 1 из 5; Mult-VAE (Colab, GPU)
  – лучшая одиночная модель для новичков; модель сайта – гибрид «популярность × ALS» (NDCG@10 = 0,355 для
  новичка с 5 оценками, значимо лучше популярности во всех сценариях; подтверждена итоговым тестом: 0,378), для
  новинок – контент по описаниям (на тесте смесь со свежестью не подтвердилась); выгрузка для сайта – 380 МБ в
  памяти при лимите Render 512 МБ –
  [model/](model/README.md);
- API на FastAPI: советы с ползунком новизны, новинки, карточка фильма с похожими по поведению людей (ALS) и по
  описанию (e5), поиск словами (совпадение с
  названием – первым), сравнение четырёх моделей, карта вкусов (t-SNE: у соседей на карте общий жанр в 87 %
  случаев против 48 % у случайных пар), сводка производительности; под нагрузкой пик 436 МБ из 512, советы –
  13 мс, советы объясняются точным разложением балла ALS («потому что вам понравились…» и вклад каждого
  оценённого фильма во всю подборку), новинки – разложением балла TF-IDF («похожа описанием на…») –
  [backend/](backend/README.md);
- сайт на трёх языках (ru/kk/en): оценка фильмов, компас вкуса, готовые вкусы в один клик, «Поделиться»
  ссылкой и QR-кодом, советы с объяснением (окно «Почему этот фильм» и панель «Почему такие советы») и
  ползунком новизны,
  новинки, поиск по описанию, карточка фильма, сравнение моделей вживую и итоги теста, карта вкусов,
  исследование, живые замеры сервера; подсказки простыми словами – [frontend/](frontend/README.md);
- CI на GitHub Actions: тесты всех частей проекта, проверка чистоты (без длинного тире и секретов) и сверка
  выгрузки модели с релизом; сайт и сервер выкладываются только после зелёного CI –
  [«Проверки и выкладка»](#проверки-и-выкладка).

## Запуск

Нужен только Docker и make:

```bash
make data      # скачать MovieLens 32M в память, собрать каталог фильмов с названиями и постерами, проверить
make check     # проверить данные и каталог
make eda       # исследование: сводки и тесты -> research/results
make figures   # рисунки исследования и моделей
make baselines # базовые модели на валидации -> model/reports
make knn       # соседи (item-kNN и user-kNN) на валидации -> model/reports
make factorization # матричная факторизация (ALS, BPR, SVD) на валидации -> model/reports
make content   # контентная модель (TF-IDF, e5) на кандидатах и новинках -> model/reports
make search    # поиск словами: 30 запросов на ru, kk, en -> model/reports
# выгрузка для сайта (шаг 6д): cd model && python export.py в Docker -> model/export (см. model/README.md)
make test      # автотесты
make -C backend test # тесты API; make -C backend run – API на http://localhost:8000 (выгрузка – model/export)
make -C frontend test # тесты сайта; make -C frontend run – сайт на http://localhost:8080
```

Для постеров и описаний нужен ключ TMDb: `TMDB_TOKEN=<Ключ доступа к API>` в файле `.env` в корне проекта
(в git не попадает).

## Проверки и выкладка

[.github/workflows/ci.yml](.github/workflows/ci.yml) – при каждом пуше и пул-реквесте в main, задачи параллельно:

| Задача | Что проверяет |
|---|---|
| data | сбор и проверка данных – 48 тестов без сети |
| research | расчёты исследования |
| model | протокол, метрики и модели – 35 тестов на маленьких данных |
| backend | API на искусственной выгрузке – 19 тестов |
| frontend | 28 тестов, проверка типов (vue-tsc) и сборка |
| чистота | во всех файлах под git – ни длинного тире, ни секретов (токены GitHub, JWT, `TMDB_TOKEN=` со значением) – [hygiene.py](.github/scripts/hygiene.py) |
| выгрузка | каждый файл из `model/export/manifest.json` есть в релизе того же размера – иначе Render не соберётся |

Выкладка – только после зелёного CI: сайт на GitHub Pages ([pages.yml](.github/workflows/pages.yml) собирает
проверенный коммит), сервер на Render – Auto-Deploy «After CI Checks Pass». После деплоя Render стоит проверить
версию запросом (например, `/api/film/7153?lang=kk` – русское название): 19.11.2026 сервис при статусе «Live»
отдавал прежнюю сборку, помогло Manual Deploy → Clear build cache & deploy.

## Структура

```
KinoCompass/
  data/      – загрузка MovieLens в память и каталог фильмов (catalog/ – в git)
  research/  – исследование данных: сводки (results/ – в git), рисунки для отчёта
  model/     – протокол проверки, метрики, модели, отчёты с результатами (reports/ – в git)
  backend/   – API сайта на FastAPI (Render): выгрузка модели в памяти, расчёты – model/site_core.py
  frontend/  – сайт на Vue (GitHub Pages): страницы, переводы, графики
  .github/   – CI (тесты, чистота, сверка выгрузки) и выкладка сайта на Pages
  Makefile   – общие команды
```
