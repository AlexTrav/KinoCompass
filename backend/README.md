# backend – API KinoCompass

FastAPI на бесплатном Render (512 МБ памяти). Базы нет: оценки человека хранятся только в его браузере и
приходят в каждом запросе. Модель – выгрузка `model/export` (шаг 6д), расчёты – те же функции
[model/site_core.py](../model/site_core.py), на которых выгрузка проверялась.

## Точки API

| Точка | Что делает | Страница сайта |
|---|---|---|
| `GET /api/health` | жив ли сервер, дата данных, размер каталога | все |
| `GET /api/films?q=&lang=&k=` | подсказки по названию на ru/kk/en (точное совпадение, начало, вхождение; самые оценённые выше); пустой запрос – популярное за год | Подобрать |
| `POST /api/recommend` | советы «популярность × ALS»; `popularity_weight` – ползунок новизны (0,4 – как на тесте, 0 – только вкус) | Подобрать |
| `POST /api/new` | новинки (фильмы 2022–2023 годов, 443) по сходству описаний – TF-IDF, вес centered | Подобрать |
| `GET /api/film/{id}?lang=` | карточка: названия на трёх языках, описание (kk – русское), «с этим фильмом смотрят» | Фильм |
| `GET /api/search?q=&lang=` | поиск словами: совпадение с названием целиком – первым, дальше e5 по смыслу | Подобрать |
| `POST /api/compare` | советы четырёх моделей на одних оценках (популярность, ALS, контент, смесь) и время каждой | Сравнение моделей |
| `GET /api/map?lang=` | карта вкусов: 5000 самых оценённых фильмов, координаты в [−1, 1] | Карта вкусов |
| `POST /api/map/me` | точка человека на карте | Карта вкусов |
| `GET /api/perf` | время ответа каждой точки (медиана, 95 %), память, время загрузки | Производительность |

Тело POST-запросов: `{"ratings": [{"id": 1, "rating": 4.5}, …], "lang": "ru", "k": 10}` – от 1 до 500 оценок
от 0,5 до 5; фильмы вне каталога пропускаются и возвращаются в `unknown` (если таких все – ошибка 422).
Документация с примерами – `/docs`.

**Как считаются ответы.**
- Советы – вектор нового человека в ALS по оценённым фильмам (одно решение системы, `site_core.fold_in`) и смесь
  рангов с популярностью за год. Оценённые фильмы не советуются.
- «С этим фильмом смотрят» – та же модель сайта для человека, которому понравился один этот фильм.
- Новинки – контентная модель, выбранная для блока новинок (шаг 6г): профиль – сумма векторов TF-IDF
  оценённых фильмов с весом «оценка минус средняя оценка человека».
- Поиск – см. [model/README.md](../model/README.md#api-сайта-шаг-7): известность переставляет первые 50
  фильмов по смыслу с весом 0,1 (единственный вес, не ухудшивший ни одного языка на 30 запросах).
- Карта – t-SNE по векторам ALS (`python export.py map`); точка человека – центр его фильмов с весом
  max(оценка − 2,5; 0), то есть не понравившиеся фильмы не тянут.

## Запуск и проверка

```bash
make -C backend test   # 13 pytest на искусственной выгрузке из 8 фильмов (tests/conftest.py), без сети
make -C backend run    # API на http://localhost:8000 с лимитом памяти 512 МБ (выгрузка – из model/export)
make -C backend load   # 100 запросов вперемешку на настоящей выгрузке: время и пик памяти
```

Образ собирается из корня репозитория; в контекст сборки идёт только перечисленное в
[../.dockerignore](../.dockerignore) (секреты `.env` и данные – никогда). На Render выгрузка скачивается при
сборке из релиза GitHub `export-2023-10-13` ([fetch_export.py](fetch_export.py)): каждый файл сверяется по
размеру и sha256 с [manifest.json](../model/export/manifest.json); не совпало – сборка падает.

**Память и скорость** (`load_check.py`, Docker с `--memory 512m`, 100 запросов): см. итоговую таблицу в
[model/README.md](../model/README.md#api-сайта-шаг-7).
